# הנחיות סמויות לתחנות המנוע

> סטטוס: **מתוכנן — לא פעיל ב־MVP.** אף בקשה לא נשלחת למודל. הקובץ מתעד את ההנחיה שתיכנס לתחנה ③ ("תיאור תמונה") כשתחובר,
> כדי שאפשר יהיה לבקר אותה עוד לפני שהיא רצה.

## תחנה ③ — תיאור תמונה (Vision)

**מה נכנס:** תמונה אחת (העותק ללא EXIF), שם הערוץ, ורשימת המאפיינים והערכים המותרים לאותו ערוץ מתוך `src/data/channels.ts`.
**מה לא נכנס:** שאלונים, ציונים, כינוי התהליך, פרשנויות מסורתיות.
**מה יוצא:** JSON בלבד. כל ערך נבדק בשער "רשימה סגורה" (בדיקת QA `observations-valid`) לפני שהוא נשמר, ונשמר עם `source: "ai"`.

### ההנחיה (system)

```
אתה מתאר תמונה עבור כלי מחקר. תפקידך לתאר בלבד — לא לפרש.

כללים:
1. לכל מאפיין ברשימה, בחר בדיוק ערך אחד מתוך הערכים המותרים לו.
2. אם המאפיין לא נראה בבירור בתמונה — בחר "לא ניתן לזהות" (אם הוא ברשימה), אחרת השמט את המאפיין.
3. אל תסיק דבר על אישיות, רגשות, בריאות, גיל, מגדר או עתיד של האדם.
4. אל תזכיר פרשנויות של כירומנטיה, גרפולוגיה או מבחנים השלכתיים.
5. אל תקרא בקול טקסט שכתוב בתמונה ואל תעתיק אותו.
6. החזר JSON בלבד, בלי טקסט נוסף, במבנה:
   {"observations":[{"featureId":"...","value":"..."}],"imageUsable":true|false}
```

### ההודעה (user) — תבנית

```
ערוץ: {channel.title}
מאפיינים וערכים מותרים:
{לכל feature שאינו computed: "- {id} ({label}): {options.join(' | ')}"}
```

### למה ככה
- **רשימה סגורה:** מונעת "המצאות" — ערך שאינו ברשימה נדחה בקוד, לא משנה כמה משכנע הניסוח.
- **בלי שאלונים בקלט:** המודל לא יכול "להתאים" את התיאור לציונים.
- **בלי פרשנות:** הפרשנויות המסורתיות נשלפות בקוד מתוך מאגר מסורות קבוע, עם רמת הראיות שלהן.
- **הערכה:** דיוק התיאור יימדד מול סימון אנושי (הסכמה בין שופטים). הסכמה בין מודלים אינה ראיה לתוקף פסיכולוגי.
