# הנחיות סמויות לתחנות המנוע

> סטטוס: **פעיל בשני מצבים (v0.4).** במסך של כל ערוץ, בכרטיס "תיאור בעזרת מודל AI", הקוד מרכיב את הבקשה מההנחיה שלהלן
> ומרשימת הערכים המותרים. **גשר ידני** (ברירת המחדל): המשתמש מעביר את הבקשה ואת התמונה למודל (Gemini, ChatGPT או Claude) ומדביק
> בחזרה את התשובה. **שליחה אוטומטית** (רשות, מפתח Gemini API אישי): אחרי שבדיקת האיכות עברה, האפליקציה שולחת את אותה בקשה בעצמה.
> מקור האמת להנחיה הוא `src/engine/bridge.ts`, ובדיקת יחידה מוודאת שהטקסט כאן זהה לו.

## תחנה ③ — תיאור תמונה (מנוע ראייה ושפה)

**מה נכנס לבקשה:** תמונה אחת (העותק הנקי, בלי EXIF), שם הערוץ, ורשימת המאפיינים והערכים המותרים לאותו ערוץ מתוך `src/data/channels.ts`.
**מה לא נכנס:** שאלונים, ציונים, כינוי התהליך, פרשנויות מסורתיות, ומאפיינים שמחושבים בקוד (גודל ומיקום הציור, מספר שורות).
**מה יוצא (התשובה):** JSON בלבד. תחנת קוד ④ ("שער הרשימה הסגורה") בודקת כל ערך לפני שהוא נשמר. ערך חוקי נשמר עם `source: "ai"` ושם המודל,
וכל ערך אחר נדחה עם סיבה. טקסט מחוץ ל־JSON (הסבר, פרשנות) לא נכנס לשום מקום.

### ההנחיה (system)

```
אתה מתאר תמונה עבור כלי מחקר. תפקידך לתאר בלבד — לא לפרש.

כללים:
1. לכל מאפיין ברשימה, בחר בדיוק ערך אחד מתוך הערכים המותרים לו, והעתק אותו מילה במילה.
2. אם אי אפשר לקבוע מאפיין מהתמונה — כתוב "לא ניתן לקבוע", והוסף "reason" עם אחת הסיבות: תאורה, טשטוש, הסתרה, זווית, אחר.
3. לכל מאפיין הוסף "confidence": גבוה, בינוני או נמוך — עד כמה הוא נראה בבירור בתמונה הזו.
4. אל תסיק מהתמונה לחץ כתיבה, מהירות או תנועה: תמונה סטטית לא מראה אותם.
5. אל תסיק דבר על אישיות, רגשות, בריאות, גיל, מגדר או עתיד של האדם.
6. אל תזכיר פרשנויות של כירומנטיה, גרפולוגיה או מבחנים השלכתיים.
7. אל תעתיק ואל תצטט טקסט שכתוב בתמונה.
8. החזר JSON בלבד, בלי טקסט נוסף, במבנה:
   {"observations":[{"featureId":"...","value":"...","confidence":"...","reason":"..."}],"imageUsable":true|false}
```

### ההודעה (user) — תבנית

```
ערוץ: {channel.title}
מאפיינים וערכים מותרים:
{לכל feature שאינו computed: "- {id} ({label}): {options.join(' | ')}"}
```

בגשר הידני שתי ההודעות מודבקות יחד בצ׳אט, והכותרת מעליהן אומרת במפורש שזו "הנחיה סמויה" שבמוצר רגיל המשתמש לא רואה.

### שליחה אוטומטית (Gemini API) — אותה בקשה, בלי העתק־הדבק

הקוד: `src/engine/autoAi.ts`. הסדר קבוע ונבדק ב־e2e:

1. **בדיקת איכות (תחנת קוד ①).** תמונה שנכשלה ("מומלץ לצלם מחדש") **לא נשלחת**. תמונה באיכות טובה או סבירה ממשיכה.
2. **תנאים:** שליחה אוטומטית הופעלה, יש מפתח, ויש הסכמה נפרדת לשליחה אוטומטית. בכף יד יש תנאי נוסף: אישור שהמפתח בפרויקט
   עם חיוב פעיל (ראו "למה ככה").
3. **הבקשה:** `POST https://generativelanguage.googleapis.com/v1beta/models/{model}:generateContent`, עם המפתח בכותרת `x-goog-api-key`.
   ההנחיה הסמויה נשלחת כ־`systemInstruction`, הודעת המשתמש וה־JPEG הנקי (base64) כ־`contents`, ו־`responseMimeType: application/json`.
   מודל ברירת מחדל: `gemini-3.8-flash` (אפשר לשנות).
4. **התשובה** עוברת באותו שער רשימה סגורה (④), ונשמרת עם `mode: "auto"`, מזהה התמונה ושם המודל (`Gemini API · {model}`).
5. **אימוץ** נשאר החלטה של אדם, בדיוק כמו בגשר הידני.

כל תמונה נשלחת פעם אחת. החלפת תמונה מאפסת את התוצאה, והתמונה החדשה נבדקת ונשלחת מחדש. המפתח נשמר ב־`sessionStorage`
(בלשונית בלבד, לא בקוד ולא ב־IndexedDB), והבקשה יוצאת ישר מהדפדפן ל־Google, בלי שרת ביניים.

### שער הרשימה הסגורה (תחנת קוד ④) — מה נדחה

| סיבה | דוגמה |
|---|---|
| ערך מחוץ לרשימה | `tree.trunk = "עבה מאוד"` |
| מאפיין שלא קיים בערוץ | `tree.mood = "שמח"` |
| מאפיין שמחושב בקוד | `drawing.size` — נקבע במדידת פיקסלים, לא במודל |
| כפילות | אותו מאפיין פעמיים — נלקח הראשון |
| מבנה לא תקין | פריט בלי `featureId` או `value` |
| מאפיין שהוסר (25.11.2026) | `hw.pressure = "חזק"` — לחץ כתיבה לא ניתן להסקה מצילום סטטי |

**"לא ניתן לקבוע" (25.11.2026):** מותר בכל מאפיין שאינו מחושב. המודל מוסיף `reason` מהרשימה (תאורה, טשטוש, הסתרה, זווית, אחר);
סיבה אחרת נשמרת כ"אחר". `confidence` (גבוה, בינוני, נמוך) נשמר רק אם הוא מהרשימה, כדיווח עצמי לא מכויל של המודל.
ביטחון המודל אינו איכות התמונה ואינו חוזק הראיות.

**אימוץ (25.11.2026):** ערך מהרשימה הוא תנאי הכרחי ולא מספיק. האימוץ נחסם בקוד (`adoptionBlock` ב־`bridge.ts`) כשאין תמונה,
כשהתמונה נכשלה בבדיקת האיכות, או כשהמודל החזיר `imageUsable: false`, גם אם כל הערכים חוקיים. גם הדוח בודק מחדש: תצפיות
של ערוץ בלי תמונה תקינה לא נכנסות אליו.

**סנכרון לשרת:** אחרי כל שינוי בהנחיה או ברשימות יש להריץ `npm run export:engine`. ה־build הרגיל לא עושה זאת. בדיקת יחידה
משווה את `server/gemini-proxy/engine.json` לקוד ונכשלת אם שכחו.

**שמירה אצל הספק:** תמונה שמועברת בגשר הידני או נשלחת אוטומטית נשמרת אצל ספק המודל לפי תנאי השירות שלו. האפליקציה לא מבטיחה
שהספק לא שומר אותה.

אחרי הבדיקה המערכת משווה את תיאור המודל לסימון הידני של המשתמש (אותה רשימה), ומציגה כמה ערכים תאמו.
המשתמש מחליט אם לאמץ את ערכי המודל לתצפיות. הדוח מציין ליד כל ערך שהגיע מהמודל, ובקרת האיכות (`no-phantom-ai`)
נכשלת אם מופיע ערך AI בלי הרצה מתועדת שאומצה.

### למה ככה
- **רשימה סגורה:** מונעת "המצאות". ערך שאינו ברשימה נדחה בקוד, לא משנה כמה משכנע הניסוח.
- **בלי שאלונים בקלט:** המודל לא יכול "להתאים" את התיאור לציונים.
- **בלי פרשנות:** הפרשנויות המסורתיות נשלפות בקוד מתוך מאגר מסורות קבוע, עם רמת הראיות שלהן.
- **גשר ידני כברירת מחדל:** בלי מפתחות, בלי שרת ובלי עלות. המשתמש רואה בדיוק מה נשלח, והתמונה יוצאת רק אם הוא מעביר אותה.
- **שליחה אוטומטית כרשות:** חוסכת העתק־הדבק, אבל התמונה יוצאת בלי פעולה נוספת. לכן היא כבויה עד שהמשתמש מפעיל אותה, דורשת
  הסכמה נפרדת, ומגיעה רק אחרי בדיקת האיכות (אין טעם לשלוח תמונה שגם אדם לא יכול לתאר).
- **כף יד רק עם חיוב פעיל:** לפי תנאי Gemini API (בתוקף מ־23.3.2026), בשירותים ללא תשלום אין לשלוח מידע אישי, Google משתמשת
  בתוכן לשיפור המוצרים, ובודקים אנושיים עשויים לקרוא אותו. בשירותים בתשלום התוכן לא משמש לכך. צילום כף יד הוא מידע ביומטרי,
  ולכן נשלח אוטומטית רק כשהמשתמש מאשר שהמפתח בפרויקט עם חיוב פעיל. כתב יד וציורים נשלחים גם במפתח חינמי, אחרי אזהרה.
- **הערכה:** דיוק התיאור נמדד מול סימון אנושי (הסכמה בין שופטים). הסכמה בין מודלים, או בין מודל לאדם, אינה ראיה לתוקף פסיכולוגי.
